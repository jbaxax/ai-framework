# Machine configuration

The two files that actually define this setup, and the reason a third one is
missing.

| File | What it decides |
|---|---|
| `gentle-ai-state.json` | Which agents are installed, the persona, and the model assigned to every SDD phase |
| `claude-settings.json` | Claude Code's own settings — default model, output style, hooks, enabled plugins |

## What is deliberately not here

`~/.claude/CLAUDE.md` is **not** versioned, and it should not be.

It is 528 lines and none of them were written by hand. The whole file is
generated by `gentle-ai` from managed blocks:

```
<!-- gentle-ai:persona -->            lines 1-73
<!-- gentle-ai:engram-protocol -->    75-177
<!-- gentle-ai:sdd-orchestrator -->   179-528
```

The persona block comes from one field in `gentle-ai-state.json`:
`"persona": "neutral"`. The model assignments block comes from
`claude_phase_assignments` in the same file. Everything else is the tool's own
template.

Committing generated output means committing something that regenerates
differently on the next `gentle-ai sync`, with no conflict and no warning. The
source is 43 lines. The output is 528. Version the source.

This is the same rule the rest of this framework follows: own what is ours,
never store or patch what a tool generates.

## Restoring on another machine

```bash
# 1. the tools
curl -fsSL <gentle-ai install> | sh          # brings gentle-ai and engram
# 2. this repository
git clone git@github.com:jbaxax/ai-framework.git ~/ai-framework
# 3. the state, before generating anything from it
mkdir -p ~/.gentle-ai ~/.claude
cp ~/ai-framework/machine/gentle-ai-state.json ~/.gentle-ai/state.json
cp ~/ai-framework/machine/claude-settings.json ~/.claude/settings.json
# 4. regenerate CLAUDE.md and the agent configs from that state
gentle-ai sync
# 5. this framework's rules, skills and ignore patterns
~/ai-framework/bin/fw link
```

`CLAUDE.md` appears in step 4. It is not copied because it is not source.

## Keeping it current

`fw doctor` compares the live files against the copies here and reports drift.
When it does, the live file is usually the newer one — Claude Code writes
`settings.json` when you change the model or the output style, and `gentle-ai`
writes `state.json` when you change a phase model.

```bash
cp ~/.gentle-ai/state.json    machine/gentle-ai-state.json
cp ~/.claude/settings.json    machine/claude-settings.json
```

Neither file is symlinked on purpose. Both tools rewrite them, and a rewrite
that replaces the file instead of editing it in place would silently turn the
symlink into a regular file and leave the repository stale. A copy plus a drift
check fails loudly instead.

## One measured cost, not fixed here

`CLAUDE.md` is 528 lines. Claude Code's documentation targets **under 200** and
states that longer files consume more context and reduce adherence.

Its four largest blocks are Model Assignments (153), the SDD workflow (130), the
Engram protocol (72), and the orchestrator rules (59) — 78% of the file, all of
it relevant only to SDD and delegation work, all of it loaded in every session
including a one-line CSS fix. The Engram protocol is carried three times over:
here, in the `engram:memory` plugin skill, and injected again by the
`session-start.sh` hook.

That is a real cost, but the lever is the tool's configuration, not this file.
Editing it is undone by the next sync, silently. Worth raising upstream rather
than patching locally.
